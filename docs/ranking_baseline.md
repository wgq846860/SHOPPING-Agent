# 排序说明

商品排序版本为 `product-ranking.v1`，报价排序为 `offer-ranking.v1`。分数表示规则下的适配程度，不能视为满意概率。

## 硬约束与购买方案

先根据结构化需求筛选商品，再核对具体Offer及连接模式。最终方案必须同时满足到手价预算、库存、配送和对应的模式、设备及售后条件。商品价、运费、必要配件和确定即时优惠均进入到手价。

## 商品排序

商品层支持价格、续航、重量、舒适度、降噪、音质、通话、游戏、便携、通勤、佩戴稳定性、无线及折叠。显式偏好在参与维度内归一化；没有支持的偏好时使用平衡预设。尚无可比评分协议的偏好会提示停用。

采用固定归一化而非候选集极值，分量贡献为 `normalized_score × weight × 100`。缺失软指标采用0.5中性值、保留原权重并给出警告；未知事实不能让硬约束放行。续航、重量与连接能力绑定实际方案及规格口径。

## 报价排序与最终结果

报价层独立使用到手价、配送、商家服务、退货及保修五个维度；显式偏好归一化，无偏好时使用平衡预设。

公开购物链路使用 `service_first`：每个商品先选择报价服务分最高的合格方案，再按该实际方案重算商品分并重排商品。价格分与推荐报价一致；最低价报价不一定胜出。

报价同分按到手价、offer_id、mode_id升序决胜，商品同分按product_id升序。内部使用未舍入分数决定顺序，前端显示可舍入。API分别输出商品与报价两组权重和贡献，理由引用实际使用的规格与事实。
